# Branding and theme tokens

Moved verbatim from `CLAUDE.md` (Branding) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

**Theme tokens live in `src/theme.css`** — a single source of truth (CSS custom properties) imported once in `main.jsx` before `App.css`. Never scatter raw hex through components; use the vars (`--bg`, `--surface`, `--border`/`--border-strong`, `--text`, `--steel`, `--muted`, `--gold`/`--gold-bright`/`--gold-dim`, `--fault`, `--font-ui`, `--font-mono`, `--radius`). **`--gold` is `#FFE629`, the published Techmen Gold** — it was `#D4AF37`, a generic web metallic gold that is not a team brand color, and the whole ramp (`--gold-bright` `#FFF06B`, `--gold-dim` `#C7B320`, `--gold-a08/a14/a24`, `--hr-regular`, `--hr-build`) is derived from it. **Gold is identity, hero type and active state, never a surface fill.** At this brightness a large gold field out-shouts the team mark on the same screen, so the large primary actions (landing CTA, access-gate submit, login submit, parent-response submit, member-application submit) are a gold label and gold border on the dark plate, with the gold FILL kept for hover and focus. **`.gate-signout` is steel** — steel border, ash label, `--surface` lift on hover — because a sign-out is neither identity nor an active state, and equal weight with the submit was wrong even as an outline. Its keyboard `:focus-visible` ring is deliberately NOT overridden: the ring is the system indicating keyboard position, not the control's identity, so a per-control ring color makes the indicator less reliable to follow, and focus is itself an active state, which is what gold is for. Every focusable control on the gate paints the same `solid 2px rgb(255,230,41)` ring. Small controls — dots, chips, tabs, progress bars, per-row buttons — stay filled, because small-area gold IS the active state. Red (`--fault`) is reserved for genuine faults/errors/destructive actions only. **Role colors** are tokens too (`--role-parent/-student/-mentor/-lead/-admin`, same pattern as `--hr-*`); render roles via the shared `RoleBadge`/`roleColor`/`topRoleOf` from `src/roles.jsx` (styled by the global `.role-badge`/`.role-dot` primitives in theme.css) so the same role is the same color on the roster, access requests, coverage matrix, nav avatar menu, and profile.

- **Site icons** (ledger 0016, feedback c6771432): `tools/icons/build-icons.mjs` builds the whole set from `public/assets/logos/Mark-Gold.svg` (refusing a mark that is not the canonical one in `PROVENANCE.json`), in the shape idea-app uses: `favicon.ico` (16, 32, 48), `favicon.svg`, `favicon.png` (32), `apple-touch-icon.png` (180, full bleed), `pwa-192x192.png` and `pwa-512x512.png` (purpose any) and `pwa-512x512-maskable.png` (the mark inside the 80 percent safe circle). Tactical HUD: the gold mark on the `--bg` plate, gold-dim targeting brackets at 180 and up. `index.html` links the ico, the svg and the apple-touch icon; the manifest in `vite.config.js` lists the three PNGs. `npm run gen-icons` verifies the mark and runs the builder (one generator, never two); `node tools/icons/build-icons.mjs --check` compares a fresh build with `public/`; `tests/site-icons.test.js` holds every reference and size.
