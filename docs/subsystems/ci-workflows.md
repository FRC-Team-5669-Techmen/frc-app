# CI workflows

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- **CI: `.github/workflows/ci.yml`, `integrate.yml` and `deploy.yml`.** The first `integrate.yml` (2026-08-30) merged a green `claude/**` branch straight into `main`; it ran once and was retired on 2026-09-02, and the current file's header says why. **`ci.yml`** runs on every push to any branch, on pull requests to `main`, on demand, and daily at 04:30 UTC: `npm ci`, then build, `npm test`, `ds:audit`, `discord:calendar:test` and `history:verify`, every step run even after an earlier one fails, with placeholder Supabase values and no credential. Its comment says the daily run tests `integration`, but a scheduled run checks out the default branch and every one has run on `main` (audit item 22). **`integrate.yml`** fires when CI succeeds on a push: it merges `main`, then every green `claude/**` branch, into the long-lived `integration` branch, and deletes each branch it merged itself; it may never write to `main`, and if `integration` conflicts with `main` it stops with nothing merged, pushed or deleted. **`deploy.yml`** merges `integration` into `main` on demand, after a typed DEPLOY confirmation that the SQL the deploy depends on has been pasted. A solo session pushes `main` itself after its local gate (see Branches, below), and `test:checkin` and `test:features` run only in that local gate, never in CI. **A push made with the default `GITHUB_TOKEN` starts no further workflow run** (GitHub's loop guard), so nothing integrate pushes is tested by CI on its own.
