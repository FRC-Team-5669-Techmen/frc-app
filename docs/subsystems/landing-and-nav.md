# Landing page and nav

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- Public landing page. NavBar: primary row is Dashboard / Schedule / Jobs / Hours ▾ / Certs, each with an inline-SVG icon (self-hosted icon set in NavBar.jsx, themed via `currentColor`; no icon dependency). **Hours ▾ co-locates the hours tools**: My Hours, Log Hours, then a staff-only divider + Team Hours / Verify Hours / Reports (Verify Hours + Reports render only for `isStaff`; non-staff see just My Hours / Log Hours / Team Hours, no divider). **Certs** is a plain link → `/certifications` for every non-parent (the Skills link and the staff Skills dropdown went with the old skills system, decision 27). The **parent branch** (`hasRole('parent') && !isStaff`) shows only Dashboard / Schedule / Team Hours. **Avatar menu**: My Profile, Certifications (every role), Weekly Survey (not for parents), Replay tour, then (if `isStaff`) a divider + **Readiness** (no header), Feedback and Announce (both *admin-only*), Surveys + a **People** group (Roster — *only if `isAdmin`* — , Applications, Access Requests w/ pending badge, Squad) + a **Live** group (Activity, Display), then Sign out. Group labels are non-clickable `.nav-dropdown-section` headers. (Verify Hours/Reports/Certify/Coverage moved OUT of the avatar menu into the Hours/Skills dropdowns.) Roster is admin-only so it only renders for admins, fixing non-admin staff hitting permission-denied. The avatar menu right-anchors via `.nav-dropdown-menu.nav-avatar-menu` (the doubled-class selector is load-bearing: it out-specifies the base `.nav-dropdown-menu { left:0 }` so the menu can't overflow the right edge) and scrolls on short viewports. A gold dot on the avatar flags pending access requests for staff (`isStaff && pendingAccess > 0`). **Kiosk is fully removed** (route, page, CSS, nav entry, context tag all deleted).

- **The tour is the feature guide** (ledger 0016, feedback aa4e3c4d): `src/featureGuide.js` lists every page (who it is for, where to find it, what it does), and `src/tourSteps.js` builds the tour from it: a spotlight where a nav anchor is on screen, and one card per area naming every other page the person can use. `tests/feature-guide.test.js` holds the guide to App.jsx's route table both ways (a new route with no guide line or written reason fails) and holds each role's tour to that role's guide pages. **The nav order** is decision 49 (measured by `tools/e2e/nav-audit.mjs`); `src/NavBar.jsx` is in ledger 0015's Owns, so it was not changed.

- **The navigation overhaul (ledger 0017, decision 49, decided).** Supersedes the NavBar description above. Top bar for members: Home, Schedule, Scouting, Robot, Hours ▾ (My hours, Log hours, Team hours, Leaderboard); one row on a phone, icon over label. Parents: Home, Schedule, Team Hours. The account menu is at most six items: Team admin (staff, with the total waiting), Sign-outs (a non-staff approver only), My profile, My standing (students) or Standing (parents), Handbook, Replay tour, Sign out. Staff tools live on `/manage` (`src/ManagePage.jsx`, catalog `src/adminTools.js`); robot tools on `/robot` (`src/RobotPage.jsx`); tiles are `src/HubTile.jsx`, styles `src/Hub.css`, icons `src/navIcons.jsx`. Home shows "Do this now" (`src/doThisNow.js`) only when something is open. `tests/nav-admin.test.js` holds the catalog to App.jsx and the menu to six.

- **What's new and the theme row (ledger 0019, decision 50).** The account menu gains **What's new** (`/updates`, between Handbook and Replay tour) and a **Theme** row of three icon radios (Light, Dark, System; `src/ThemeSwitch.jsx` compact, clicks do not close the menu). `/updates` (`src/UpdatesPage.jsx`) lists `src/updates.js`, the release log, newest first, one card per release grouped by date, with an Open link where the release has a route; new releases are added at the TOP of that file in student copy (short lines, no em dashes, no weekday names). The unread rule is `hasUnread(UPDATES, readSeen())`: the newest entry's `date|title` against the one stored under `techmen:updates-seen` when `/updates` was last opened (localStorage; a private window just shows the dot). While unread, the avatar carries the dot (also for a student with nothing waiting), the menu item carries a small dot, and Home ends with a one-line strip naming the newest release, lit as New. Opening `/updates` marks it seen and the nav dot goes out at once (the `techmen:updates-seen` window event). `tests/updates.test.js` holds ordering, the unread rule (same-day release, rolled-back build, removed entry) and every route; `tools/e2e/features/theme-updates.mjs` drives the dot both ways. The menu is six entries for everyone and seven for a student sign-out approver (decision 50, default).
