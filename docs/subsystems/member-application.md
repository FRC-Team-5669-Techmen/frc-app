# Member application

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- **Member application** (`supabase/member_applications.sql` + `supabase/member_applications_rls_test.sql` + `src/MemberApplication.jsx`/`.css` + `src/ApplicationsPage.jsx`/`.css` + `src/seasons.js`). The per-season onboarding form that replaces the Google Form, **authenticated only** (no public route, no anon table, no anon insert policy — identity is `auth.uid()`, since every member record descends from `auth.users`). **Renders in the AccessGate slot in `App.jsx`** — after session + `approved`, before the app shell, no NavBar — when the signed-in member has no `member_applications` row for the current season; submitters go straight to the dashboard. **Gated to the member track only**: staff (`mentor/lead/admin`) and parent-only accounts are never asked (they can't truthfully answer pathway / parent contact / build-season commitment, and gating them would lock them out) — one `loadApplicationState` branch in App.jsx. The `/checkin` + `/checkin-volunteer` fast paths are **deliberately let through** so a member mid-session is never blocked from signing out; the gate check also **fails open** if the query errors (deploy-before-migration can't trap anyone). Multi-step form (8 steps → 6 for returning members) with a progress bar + back/next, native HTML5 validation only, all answers in component state, **written once on final submit** so a partial fill never creates a row; no form/validation library added. `member_applications` is one row per member per season (`unique (member_id, season_id)`, `season_id` → `seasons.id` uuid, **"current season" is the existing app rule** — the season spanning today, now shared in `src/seasons.js` (`resolveCurrentSeason`) instead of inlined in HoursBoard). CHECKs: pathway (7 values incl. `Freshman - in rotation`), the 12-value subteam vocabulary (`src/subteams.js`), pairwise-distinct ranked choices, Yes/No/Sometimes availability, and the conduct acknowledgment unstorable-as-false (the build-season one's CHECK was dropped by `supabase/member_applications_drop_build_ack_chk.sql`, so it records whether the student saw and checked that box). **Contact fields live here and NEVER on profiles** — `profiles` is `select using (true)` to every authenticated member, so parent phones there would publish to the whole team. **RLS**: `insert with check (member_id = auth.uid())`, `select using (member_id = auth.uid() or is_staff())`, and **no update/delete policy for anyone** — corrections route through SECURITY DEFINER per the `admin_member_management.sql` rationale (silent 0-row client writes); the one such path today is `staff_set_discord_confirmed(p_application, p_confirmed)` because `discord_server_confirmed` is staff-set. Grants are `select, insert` only, plus an explicit `revoke all … from anon` (the bootstrap `ALTER DEFAULT PRIVILEGES` grants anon on new public tables, so policy scoping alone is not the anon barrier). `member_applications_rls_test.sql` is a **mutation** test (runs inside a `begin … rollback`, safe on live data): a member can't read another member's row, can't insert with a foreign `member_id`, can't update their own row, and anon has no table privilege — each case fails loudly if the block is missing, with a positive control so a broken-shut policy can't fake a pass. **Three fields write to `profiles`** (already there, already team-visible by design) via the existing direct `profiles update own or admin` policy, same path ProfilePage uses: `nickname` (preferred name), `grad_year` (**integer year, never a grade label** — the dropdown is labeled with this year's grade), `shirt_size`. **Never writes `profiles.subteams`** (staff-set placement) or `profiles.disciplines`. **Prior-experience answers are self-reported and create NO `member_skills` rows** — certification is granted, not claimed; they're display-only to staff. Phones digit-sanitize on change (LoginPage pattern); parent email is `type="email"`. **Returning-member path**: skips prior experience, prefills identity/school/parent/Discord from the most recent prior row, and skips logistics **only when that prior row carries the NOT NULL emergency contact**; subteam interest + commitment are always asked fresh. The meeting schedule is one exported `MEETING_SCHEDULE` constant rendered above the commitment step, which `build_season_acknowledged` references — **the build-season line is still a TODO placeholder**. **Staff view `/applications`** (`ApplicationsPage`, staff-guarded like the other staff pages, in the avatar People group, `APPS` context tag): season picker (defaults to current), search, submitted/returning/not-in-Discord stats, first-choice counts, a row-click full detail modal, the Discord-confirmed toggle, and a **client-side CSV export of the full table** (no Sheets, no Apps Script, no Google API). **`select('*')` on this table no longer works from a client** — see the parent response flow below; both call sites use `APPLICATION_SELECT` from `src/applicationFields.js`.
