# Push notifications

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- Push notifications (`supabase/push_notifications.sql` + `supabase/functions/`). Web push, opt-out per category, sensible defaults, quiet hours, batched + deduped. **SW moved to vite-plugin-pwa `injectManifest` mode** with a custom `src/sw.js` (precaches `self.__WB_MANIFEST` — offline preserved; `skipWaiting`+`clients.claim` keeps autoUpdate-on-reload; handles `push`/`notificationclick`). Schema: `push_subscriptions(endpoint pk, member_id, p256dh, auth, …)` own-row RLS; `profiles.notification_prefs` jsonb (master `enabled`, `task_signoff`/`event_reminder`/`parent_digest` on, `shop_status` OFF, `quiet_hours` 21:00–07:00 in America/LA); `events.mandatory` bool; `notifications_sent(member_id, kind, ref_id)` dedupe ledger (RLS locked, service-role only). Edge Functions (`send-push` + `cron-notify`, each self-contained/single-file so they deploy via the Dashboard editor, using `npm:web-push`, gated by an `x-push-secret` header, deploy with JWT verification off): prefs/quiet/dedupe checks, VAPID sign, prune 404/410. Triggers: a `task_claims` AFTER UPDATE trigger (`notify_task_signoff`) calls send-push via `pg_net` on the verify_task transition (completed=approved, →claimed=rejected); pg_cron calls cron-notify for batched event reminders (≤24h, RSVP'd going/maybe OR mandatory, one per member/day), the parent daily digest (8pm PT, one per parent), and optional shop_status. More triggers in `supabase/notification_triggers.sql`: **schedule_change** (statement-level events INSERT/UPDATE/DELETE triggers → broadcast to schedule_change-opted members; series-coalesced — bulk insert/series delete are one statement = one push, series edit's N updates collapse via a shared `sched:edit:<series_id>:<day>` ref_id in the dedupe ledger); **skill_signoff** (member_skills→certified trigger, mirrors notify_task_signoff; member_skills has no pending state so only certify fires); **checkin_reminder** (evening pg_cron → cron-notify reminds anyone with an open check-in, once/day, default off). **Catalog (the things that send): task sign-off→claimant, event reminder (batched), schedule changes (series-coalesced), shop open/closed (opt-in), skill sign-off→member (toggle hidden since decision 27: nothing certifies `member_skills` any more), check-in reminder (evening, opt-in), parent daily digest. `job_assignment` + `announcements` prefs keys exist but their toggles are HIDDEN in the UI (no underlying feature yet — un-comment in NotificationsPanel CATEGORIES to restore). Explicitly never: job-claimed, generic activity, individual check-ins.** `/checkin` imports none of it. **Deploy is held until the rest is live** — see the DEPLOY block in the SQL: needs VAPID keys (`VITE_VAPID_PUBLIC_KEY` frontend + `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT`/`PUSH_SECRET` function secrets), the two functions deployed `--no-verify-jwt`, and the `private.push_config` row filled (until then the trigger/cron no-op).
