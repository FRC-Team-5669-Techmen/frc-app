- **In-app feedback + admin inbox** (`supabase/feedback.sql` + `supabase/feedback_rls_test.sql` + `src/FeedbackWidget.jsx`/`.css` + `src/FeedbackPage.jsx`/`.css`). A global "send feedback" button on every authenticated page, and an admin-only inbox at `/feedback`. **`public.is_admin()` is NEW here** — same shape as `is_staff()` from `skills_catalog.sql`, narrowed to the admin role; it exists because this is the first table whose read policy is admin-only rather than staff-wide, and nothing else was repointed at it. `feedback(member_id, category[bug/idea/feedback], message, image_paths jsonb, route, viewport, user_agent, status[open/reviewed/dismissed], reviewed_by, reviewed_at, created_at)` as `feedback.sql` made it; migration 0002 (see the feedback console bullet) makes `category` nullable, adds `tried` and `build`, and moves `status` to new/seen/in_progress/done/wont_do/spam, mapping existing rows in place. **RLS: insert own (`member_id = auth.uid()`), select/update `is_admin()`, and NO DELETE POLICY FOR ANYONE** — an inbox is triaged, never pruned. Two consequences written down at the policies: the member who filed a report **cannot read it back** (one narrow policy instead of two overlapping ones; acceptable because the widget has no history view and no edit-after-submit), and `revoke delete, truncate ... from authenticated` is required because the bootstrap `ALTER DEFAULT PRIVILEGES` grants authenticated everything on a new public table — without it a stray delete fails SILENTLY at 0 rows instead of raising. **Storage bucket `feedback` is PRIVATE, deliberately unlike `jobs`**: the jobs bucket is public because it holds reference photos of parts, whereas a feedback screenshot is a picture of the app mid-use and routinely frames other members' names, hours and contact rows. So read is `is_admin()`, insert is authenticated (bucket_id only, same shape as jobs), delete is uploader-or-admin — and the admin page must mint `createSignedUrl`s (600s TTL, re-signed on every list load, never cached indefinitely) because a private bucket has no public URL at all. **MEASURED CAVEAT recorded at the policy: the `owner = auth.uid()` half of the delete rule is DEAD for a non-admin**, because a DELETE's row lookup goes through the admin-only SELECT policy, so their own delete matches 0 rows; a member's images orphan in the bucket if the row insert fails after upload, and only an admin can clear them. **The widget is mounted ONCE in `App.jsx`'s `ProtectedLayout`**, lazy with its OWN `<Suspense fallback={null}>` — sharing the app-level boundary would put the whole shell back on the splash while it loads. Three image-input paths all funnel into one queue (`addFiles`): file picker, drag-and-drop, and **paste bound to the whole panel rather than just the textarea**, so a clipboard screenshot lands whether or not the caret is in the message box. Telemetry (route, viewport, user_agent, and since 2026-10-01 the build) is gathered automatically and shown in the panel before sending, and `member_id` comes from the session — the member writes a message and, if they like, a type and what they tried. **The type is optional and none is preselected** (Mr. Pina, 2026-09-03); before 0002 is pasted an untyped report still saves, through an insert ladder that falls back to `'feedback'`. Images upload first, then the row is inserted carrying their paths. **`/feedback`** is admin-gated inside `FeedbackPage` (`hasRole('admin')`; the route in `App.jsx` carries no gate of its own, and RLS is the real boundary) and lives in the NavBar avatar menu next to Readiness with a badge counting `new` and `open` reports, admin-only (`isStaff` would be wrong: the ask was "as an admin", and a report can quote anything the member had on screen). It shows a thumbnail strip and opens an ApplicationsPage-shaped `fbp-modal-*` detail with full telemetry and full-size images; its filters, status tabs, export bar and bulk moves are the 2026-10-01 rebuild (the feedback console bullet). Status moves go through the admin RPCs 0002 adds; before 0002 the console moves one report at a time by a plain client update in the old spelling. **"Copy for Claude"** writes a plain-text block (category, author, timestamp, route, viewport, user agent, status, the message verbatim) to the clipboard, per row and as a multi-select `Copy N as prompt` that concatenates blocks oldest-first with a rule between them; **it deliberately embeds NO signed URL** — one would be dead by the time anyone read the pasted prompt, and scattering a link to a screenshot of other members' data into a chat log is an unnecessary exposure, so it states the image count and where to view them. Selection is scoped to what is on screen, so a filter change drops a hidden row rather than silently carrying it into the bulk copy. **The page's classes are `fbp-` and the widget's are `fb-`** — both stylesheets load together on `/feedback`. **EXPLICITLY NOT BUILT: no automatic client-error capture (decision 15), no email/Discord notification (this is a pull inbox; decision 16), no edit-after-submit.** **The check-in fast paths do NOT get the widget** — `/checkin` and `/checkin-volunteer` sit OUTSIDE `ProtectedLayout` in the route table, which keeps the NFC path light as the architecture rule requires.
