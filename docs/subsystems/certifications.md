# Certifications

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- **The old skills certification system and the Study page are RETIRED** (decision 27, answered 2026-10-14: "it teaches nothing"; ledger 0006, `docs/history/upbeat-keller-i4t69g.md`). `/skills`, `/certify`, `/coverage` and `/study` are `<Navigate to="/certifications">` routes, and `SkillsCatalog`, `DisciplinesCatalog`, `MemberSkillsHome`, `MemberSkillsPanel`, `CertifyPage`, `CoverageMatrix` and `StudyPage` are deleted (git history keeps them). The dashboard's Skills, Coverage and Study tiles became a Certifications tile (IDEA codes held, or for staff the catalog size and sync state), Profile and `/members/:id` point at `/certifications`, the parent dashboard's cert chips became a link, the cert-request queue and its NavBar/dashboard badge count are gone, Readiness no longer renders Safety cert coverage or Study pulse, and the Skill sign-offs push toggle is hidden. **No table was dropped and no row deleted**: `skills`, `member_skills`, `cert_requests`, `task_required_skills`, `study_sessions` and `disciplines` keep their rows, and `readiness_summary` still computes the two dropped cards. `tests/retired-skills.test.js` holds the retirement (redirects, no link to a retired address, nothing but the Jobs page fallback reads the old tables). The drop statements, and the three functions that must be re-defined before any drop, are in the history entry. `ProfilePage`'s disciplines picker still reads `disciplines`, which can no longer be edited in the app.

- **IDEA certifications mirror** (`supabase/migrations/0001_idea_certifications_mirror.sql` + its `_rls_test.sql`, `src/ideaCerts.js`, `src/CertificationsPage.jsx`/`.css`, `docs/IDEA_CERTIFICATIONS_SYNC.md`; added 2026-10-01). Mr. Pina, 2026-09-30: certifications are the official IDEA certifications, awarded only in IDEA Classroom, and this app keeps a read-only, one-way copy. The only writer is `idea_cert_sync(p_secret, p_snapshot)`, which checks a shared secret against the bcrypt hash in `idea_cert_sync_key`, validates the whole snapshot before touching a row, replaces `idea_cert_catalog` and `idea_cert_holders`, and logs every accepted or refused snapshot to `idea_cert_sync_log` (decision 34); no client can write the mirror, and holders are keyed by lowercased school email, not member id (decision 33). `/certifications` (avatar menu, every role) shows the catalog, holders and "Your certifications", where only an active, unexpired row counts as held; a parent-only account sees its linked students' rows only. The contract doc is authoritative and `tests/idea-certs-contract.test.js` holds it to the SQL. **The IDEA side** is the portal at ideabosco.com/certifications (`pina-hash/idea-app`), live 2026-10-15 per Mr. Pina; 0001 is applied and the sync secret set per the ledger 0006 prompt, which nothing in this container can check. Every holder row links to `https://ideabosco.com/certifications/verify?serial=<serial>`, the page says certifications are earned and awarded only there, and an admin gets **Export sync log** (decision 34): one zip of `README.txt`, `sync-log.json` and `sync-log.csv` holding every `idea_cert_sync_log` row (`src/ideaSyncLogExport.js`). **Job gating reads the mirror** (migration `supabase/migrations/0012_jobs_idea_cert_gate.sql` + its test, `src/jobCerts.js`, `src/dev/fixture/features/jobcerts.js`; 2026-10-16, ledger 0006): `task_idea_cert_requirements(task_id, code, source[admin/mapped/unmapped], set_by, set_at)` names at most one IDEA code per job (a null code is a decided "no requirement"; no row is none either; deliberately no foreign key to the catalog, which every sync replaces wholesale), written only by `admin_set_task_cert(p_task, p_code)` (`is_admin()`, the code must be in the catalog); `claim_task` is replaced with the same checks plus `idea_cert_caller_holds(code)`: an active, unexpired mirror row for the caller's lowercased `auth.users` email (decision 33). It reads neither `member_skills` nor `task_required_skills`. 0012 carries each job's old skill requirement over only when every required skill names exactly one catalog code (by code or name, trimmed, any case) and they all name the same one, records the rest as `unmapped`, and ends with a report of every job it looked at. Before 0012 is pasted the Jobs page detects the missing table (`jobCertMode`) and runs the old path unchanged. Proven by the 0012 test (27 checks) and 19 mutants on `tools/sql-harness/`, `tests/job-certs.test.js`, and `npm run test:features` (`job-certs`, 109 checks).
