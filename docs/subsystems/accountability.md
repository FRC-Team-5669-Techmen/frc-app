# Accountability and eligibility

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- **Accountability / eligibility tooling** (`supabase/accountability.sql` + `src/accountability.js`). Builds on categories + the integrity work. **(1) Hour goals** — `hour_goals(member_id null=team default, season_id, target_hours, categories text[] null=all categories, updated_by/at)` with partial unique indexes (one team default per season, one override per member/season); RLS members-read-team+own / staff-read-all, writes via SECURITY DEFINER `set_hour_goal(member,season,target,categories[])` / `clear_hour_goal(member,season)`. Effective goal = member override else team default (`effectiveGoal`); progress = sum of the goal's categories from `buildBreakdown` (folds attendance-derived + verified logged hours), via `hoursTowardGoal`/`goalCategoryKeys`. **Category scope choice**: a goal counts toward all categories by default, or a chosen subset stored on the goal row (`categories`); empty = all. **Per-season** (goals are a season minimum). UI: a **progress bar on My Hours** (active-season effective goal); a **Goals / who's-behind view** on Team Hours (`HoursBoard`, third view toggle) sorted by gap-to-goal descending, with staff team-default config + per-member override editor (`GoalEditor`, category toggle chips). **(2) Anomaly flags** (`detectAnomalies(events,{exempt})`, advisory — never auto-deletes): `double_in` (an IN left open before another IN — covers orphan-IN-without-OUT and two-INs-no-OUT, the same pattern under sequential pairing; a trailing open IN is the live session, not flagged), `overlap` (derived sessions whose real intervals intersect), `capped` (sessions clamped by `MAX_SESSION_MS`), `geofence` (an IN with `attendance_events.geo_ok = false` whose member isn't currently `geofence_exempt`). Surfaced in an **Attendance Anomalies** advisory list on `/verify-hours`. Detection is still advisory and never mutates anything, but `capped` and `double_in` cards now carry a **Resolve** button that swaps the list for a `MemberHoursAdmin` scoped to that member (`initialMemberId` + `focusEventIds`), scrolls the flagged `attendance_events` row into view and gives it a ~2s gold highlight. **No resolved/dismissed state is stored** — "Back to anomalies" re-runs `fetchAnomalies()`, so a genuinely fixed item drops off by itself. `overlap` and `geofence` get NO button on purpose: an overlap needs a judgement about which of two sessions is wrong and a geofence flag is about where a member was, so neither resolves by editing one row. When the focused row is an IN with no check-out (a stale capped session, or the orphaned IN of a `double_in`), `EventRow`'s `autoFocusEmpty` opens it in its existing edit mode and adds one field — the missing check-out time, written through the same `staff_add_event` RPC. **That field is ALWAYS EMPTY and is never seeded with the session's capped `effectiveOut`, the auto-close cutoff, or any other computed instant**: a pre-filled plausible time is the fastest way to get a wrong one saved into an hours ledger, so staff type what they actually know. The capped value stays a read-only display elsewhere. **What that rule costs is precision nobody has** — an exact minute for a session months old — so the block offers two ways out that do not require one, both additive to `autoFocusEmpty` and neither touching the normal edit path. **(a) A half-hour stepper**: `-30m`/`+30m` build the check-out as an offset from the check-in with a live "Session length: 1h 30m — ending 9:30 AM" readout (the ending date is named too when it crosses midnight). `outTime` stays the SINGLE source of truth, which is what keeps the stepper and the datetime-local fallback from fighting: a step reads whatever is in the field right now, so typing a time becomes the baseline the next click adjusts from, and no separate offset state can drift out of sync. The low end clamps at the check-in — stepping down to or past it CLEARS the field, which is both the no-zero-length-session rule and how the nothing-entered starting state is restored; the high end is deliberately unclamped. The starting offset is 0 and the field still mounts at `''`. **(b) A one-click void** (`Cancel — don't count this session`, `mha-btn-danger`) for when no honest check-out exists at all, on the existing `staff_void_event` RPC the row's own Delete already calls. Its FIRST click fills the shared reason field with a default sentence and does NOT void — so the required-reason field is the confirmation step exactly as it already is for Delete, rather than a second dialog, and a misclick is harmless. That default is a static sentence about why staff voided the row, never a claim about the student's session, which is why it may be pre-filled where a timestamp may not. **RESOLVING NOW HAPPENS IN THE ANOMALY LIST ITSELF for the common case, and the eventIds shape is what decides which case that is** — `double_in` always (eventIds[0] is the orphaned IN), and `capped` only when `eventIds.length === 1`, which is `sessionsFromEvents` handing back a still-OPEN session (`outId` null) that has run past `MAX_SESSION_MS`: the true missed-checkout case, where `a.at` is the check-in. **`capped` with length 2 means a REAL check-out event exists** and the pair merely exceeds the cap — adding a second OUT would not fix that, so it is an EDIT and keeps the old route into `MemberHoursAdmin`, labelled `Open member events →` with a note saying why. Each inline card expands in place (no panel swap, no member search, no full-ledger fetch, no scroll-and-highlight) and carries **one-click duration presets (30m/1h/1h30m/2h/2h30m/3h) over the ±30m fine adjust**, the shared readout, a reason field, `Add check-out` and a two-click `Don't count this session`. On success the item is spliced out of the local array and the mentor's next click is the next card — there is no Back. **BULK**: a checkbox per inline-resolvable card, a select-all scoped to only those, then `Void N selected` or `Set N selected to <duration>` — the latter applied as a **LENGTH from each item's own check-in**, never one shared clock time. Bulk loops the SAME single-event RPCs sequentially (no batched endpoint, and deliberately not `Promise.all`: each call writes an `attendance_audit` row, and a burst is both the shape most likely to trip a rate limit and the one whose partial failure is hardest to report honestly); a progress counter makes the few seconds visible. **A failed item is never counted as done** — it stays in the list with its own inline error and the result line says so. **The bulk result line renders OUTSIDE the bulk bar**, because a successful bulk action empties the selection and unmounts the bar, so a note inside it vanished at the exact moment it had something to say (found by running it, not by reading it). **`src/hoursResolve.js` is the shared pure module** both surfaces call — `stepMinutes`/`setPreset`/`endInstantMs`/`minutesFromInstant`/`resolveReadout`/`DURATION_PRESETS`/`STEP_MINUTES` — no React, no Supabase: it computes values and the call site owns the state and the RPCs. **ITS CANONICAL MODEL IS AN OFFSET IN MINUTES WITH `null` MEANING NOTHING ENTERED**, which is the no-pre-filled-timestamp rule expressed in the type — there is no zero-ish starting instant to render, so a caller cannot accidentally show one, and `endInstantMs` is the single place an offset becomes a timestamp. A preset REPLACES the offset rather than chaining onto it. The per-member `EventRow` keeps its datetime-local field as ITS source of truth and re-derives the offset each render, so that surface is unchanged in behaviour and gained only the presets. **The reason text is shared across every resolve action for one page load** (single and bulk alike) so a mentor clearing a backlog types it once; it carries no time and no claim about a student, and nothing persists it. `unclosedInIds()` in MemberHoursAdmin does that pairing itself rather than reading `sessionsFromEvents`, which overwrites an open IN when a second IN arrives and so produces no session at all for the orphan. Anything else is still fixed via Team Hours edit/void/manual. **`attendance_events.geo_ok`** (bool, nullable) is set at check-in: `true` = geofence verified, `false` = exempt member skipped it, `null` = legacy / staff-bypass / check-out. **(3) Attendance vs hours** — `daysPresent(events,{since,until})` = distinct calendar days with an IN; shown **separately** from clocked hours: a "Days present" stat on My Hours' goal card, a **Days** column on the Team Hours by-member table, and a Days column in the Goals view. Meeting attendance is scoped as days-with-a-check-in (decoupled from the schedule; tying to specific `events` rows is a possible refinement).
