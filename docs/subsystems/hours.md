- My Hours and Team Hours board (aggregates attendance events live). **Hour categories** are the single axis: `build`/`outreach`/`volunteer`/`competition` (four; `fundraising`/`mentoring` were removed), defined once in `src/categories.js` (the `CATEGORIES` array + `--hr-*` color per key), color-coded consistently across both boards. **Aggregation** (`buildBreakdown` in hoursUtils, which since 2026-10-01 is `breakdownFromSessions` over `sessionsFromEvents`, one pairing of the whole ledger; it used to pair IN/OUT inside UTC-date groups and dropped every session crossing 00:00 UTC, see the hours day rule bullet): each attendance session is attributed to its **IN** event's category (normalized; legacy `'normal'`/null → `build`); attributing by the IN side keeps it robust to the auto-close 'out' (which need not carry one). Verified `logged_hours` rows fold into the same buckets via `loggedTypeToCategory` (`volunteering`→`volunteer`). `buildBreakdown`/`sumBreakdown` return `{ ...all four categories, total }`; selects feeding it pull `category` (HoursBoard, MyHoursPage); `sessionsFromEvents` carries the (normalized) per-session category. Generic worked-time totals (`computeHoursMs` → ParentHomePage Today/Season, RosterPage sort) remain full all-category totals — they're unlabeled aggregates, not a per-category bucket. **Team Hours displays the full split**: a category totals strip (each category + a grand total) above the By-member table; the **By-member table** renders one column per category (iterated from `CATEGORIES`) + Total + Status; the **drill-down** modal opens with a per-member category breakdown + grand total and tags each session row with its category; the **admin CSV** labels every session/logged row by category. Team Hours has a **By member / Matrix** view toggle. **Matrix** = coach-timesheet member×day grid of **total attendance hours (all categories)** — `hoursByDay()` in `src/attendanceHistory.js` sums every on-site session per LA day (it replaced HoursBoard's private `attendanceHoursByDate`, which kept the old UTC-date pairing, so a member's Matrix total now equals their By-member attendance total; the matrix is a physical-presence timesheet; the category split lives in the by-member table + drill-down, reachable by clicking a cell). One row per member incl. zeros, one column per calendar day from season start through today, Sat–Fri weeks each with a subtotal column, a season Total column, a Daily Total footer row, and a sticky member-name column; sortable by Name/Total/each weekly subtotal, default Total desc; needs one season so the 'All Time' tab falls back to the active season. On opening Matrix it **auto-scrolls today's column into view** (`todayThRef` + `scrollIntoView` on the th whose key === today). **Drill-down (both views)**: clicking a member row (By member) opens a modal of their sessions grouped by LA day for the season (the shared `src/AttendanceHistory.jsx`, the same view `/display` opens, with HoursBoard passing in its staff controls); clicking a non-zero matrix cell opens that one member+day's sessions. Each session lists sign-in time, sign-out time (or "— open —"), location (entrance, → exit if different), duration, and category — read straight from the stored `attendance_events` via `sessionsFromEvents`, never recomputed. The admin CSV (By-member view) is every member's full sign in/out history (incl. entrance/exit + category columns) + logged hours; in Matrix view it's the member×day grid with weekly subtotals + Total instead. **Entrance/exit is `attendance_events.location`** — already captured per event (the NFC tag's `?loc` param set by CheckinPage); surfaced via `sessionsFromEvents` (inLoc/outLoc) + `fmtLocation` in hoursUtils. The wide members table scrolls horizontally (`board-table-wrap` is `overflow-x:auto`). My Hours adds an all-time **by-category** breakdown (colored bars), a 6-week trend, recent sessions (each tagged with a non-build category), and a This Week stat, every figure derived once from the same rows by `src/myHoursModel.js`; This Week and the trend count only sessions that count toward totals (decision 37), and a voided session is listed with a "not counted" marker. Shared category helpers live in `categories.js`, re-exported from `hoursUtils.js` (`CATEGORIES`/`categoryLabel`/`categoryColor`/`loggedTypeToCategory`/`emptyBreakdown`) alongside `sessionsFromEvents`. **`logged_hours.type` is aligned to the category set** (`supabase/session_integrity.sql` migrated legacy `'volunteering'`→`'volunteer'`; `supabase/categories_reduce_event_kind.sql` then reduced the constraint to the four current categories and re-tagged `fundraising`/`mentoring`→`outreach`); `LogHoursPage` offers all four (manual entry has no NFC tag to derive from, so the user picks; display order Build/Volunteer/Outreach/Competition), chips colored by `categoryColor`. The read-time `loggedTypeToCategory` map still folds any stray `'volunteering'`→`'volunteer'`.

**Weekly totals and pauses (codex-frc-feedback, 0048).** `weeklyHours.js` defines Monday through Sunday by Los Angeles calendar dates, including DST. Dashboard and My Hours use that same calendar week, the IN date attribution rule, counted sessions and verified logs on the work date, never the approval time. My Hours previously counted verified logs already but called a rolling seven-day period This Week. The dashboard previously omitted logs and now pages attendance, logs, reviews and adjustments; Today and active Season include verified work, and the season includes staff adjustments. Reads refresh on return and every 30 seconds; a failure retains the last good result and says so.

The member can pause or resume hours on the dashboard without creating an IN/OUT. The server writes intervals to `attendance_events.pauses` on the original IN through `set_session_paused(in, paused)`. Retries of the same state are idempotent; clients cannot forge the column; only an approved active student/staff member can change their own current session. Checkout closes any open interval. `sessionsFromEvents` unions and clips intervals inside the existing wall-time cap, returns net `ms` and `pausedMs`, and every credited-time reader includes the field. Reads request their existing fields plus pauses through `withSessionPauses`, which retries the same read without that column only for a missing-column code, preserving narrow projections during rollout. Dashboard, recent sessions and shared attendance history show excluded time; presence and sign-outs show Hours paused while keeping the member present. SQL standing, volunteer letter hours and readiness subtract the same interval union. No historical time is backfilled or guessed. SQL tests run on disposable data; production application is established separately by Migrate/catalog evidence.

Standing weekly FRC requirements now include verified non-FLL logs through `_standing_week_hours`; `_member_hours` remains attendance-only for team readers that add verified logs separately. Approval/rejection transitions use the worked LA date and the same Monday/Sunday boundaries.
