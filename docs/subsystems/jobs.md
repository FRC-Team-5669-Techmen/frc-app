# Jobs

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- Multi-claim jobs (`supabase/multi_claim_jobs.sql`, refactors jobs_board). Per-claimant lifecycle lives in `task_claims(task_id, member_id, status[claimed/submitted/completed], …)`, PK (task_id, member_id). `tasks.max_claimants` (int, default 1 = solo, null = unlimited, N = capped). `tasks.status` is now staff-controlled **availability** (open/closed/completed), no longer auto-driven by a single claim. RLS: task_claims readable by all authenticated, staff write/delete; members transition only via the SECURITY DEFINER RPCs. **claim_task locks the tasks row FOR UPDATE before counting claims (race-safe capacity).** **Cert-gating moves to the IDEA mirror with migration 0012** (`supabase/migrations/0012_jobs_idea_cert_gate.sql`, `src/jobCerts.js`; see the IDEA certifications bullet); what follows is the old gate, which the Jobs page keeps until 0012 is pasted. **Cert-gating was collective (`supabase/jobs_collective_certs.sql`)**: required certs are covered by the *group* of claimants, not one person. A member may claim a cert-gated job if they hold **at least one** required cert (none → blocked); the job is "fully staffed" when the union of claimants' certs covers every required cert. The Jobs detail shows per-cert coverage (which claimant covers each, which are uncovered) and the list row shows a "⚠ N cert gap" badge until covered. JobsPage loads claimants' certified `member_skills` into `certsByMember` to compute coverage client-side. **verify_task signature changed to `verify_task(p_task, p_member, p_approve)`** — per-claimant sign-off; update every caller. Staff close/complete/reopen by updating `tasks.status` directly. **Job creation is open to all members (`supabase/jobs_open_create.sql`)** — the "+ New job" button + create form show for any signed-in member, and a permissive `tasks insert own` RLS policy (`with check created_by = auth.uid()`) sits alongside the staff for-all policy; a matching `task_skills insert own task` policy lets a creator attach required certs to their own task. **Edit/delete stay staff-only** (no member UPDATE/DELETE policy; the edit form is reachable only via the staff actions). **Deprecated (kept, not dropped — live data): `tasks.claimed_by`, `tasks.verified_by`** — unused by the new logic. `readiness_summary.sql` was updated to read task counts from `task_claims` (re-run it alongside the migration). **Jobs page browse UI**: compact collapsible list rows (status pill, title, due/claim/cert meta) grouped by subteam; clicking a row opens a detail modal with the full job + all claim/staff actions. Title search + sort (status/due/cert/title). Status is a derived color scale — open=green, in progress=amber (≥1 active claim), needs-review=red (≥1 submitted claim awaiting sign-off), completed/closed=gray (there is no literal "blocked" task state; needs-review is the red bucket). `tasks.due_date` (date, nullable, `supabase/tasks_due_date.sql`) added with a form field + overdue flag. **Job content + admin controls (`supabase/jobs_content.sql`)**: `tasks.links`/`tasks.images` (jsonb arrays) for reference links + uploaded images shown in the detail; `task_updates` (progress thread: body + optional image, posted by a claimant or staff, RLS-gated); **time tracking reuses attendance** — `attendance_events.job_id` stamps a check-in session with a job, set by the member via the `set_session_job(p_task)` RPC ("I'm on this job" button: requires an active claim + being checked in; links the current open session), total per member per job shown in the detail; `admin_revert_claim(p_task, p_member)` (admin only, confirm dialog) undoes an approved/completed claim back to 'submitted' and reopens the job if it was completed. **First use of Supabase Storage**: public bucket `jobs` (paths `task/<id>/…` and `update/<id>/…`); public read, authenticated upload, owner/staff delete — policies in the same SQL file (if `create policy on storage.objects` errors on ownership, create the bucket + policies via the Storage UI instead).
