# Presence board

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- Presence Board (`/display`, a wall display staff open from the avatar menu; the route itself has no role gate, so any signed-in member can open it, and the student dashboard's Team pulse tile links there): who-is-present by the shared rule in `src/attendanceState.js`, read from `presenceSinceISO()` so a session open across LA midnight still shows, approved members only, subteam-grouped, live via 15s polling (realtime is not wired in the project). Renders **inside ProtectedLayout** so the NavBar + avatar stay visible. A staff viewer can click a name to open that member's attendance history, read-only (the attendance history bullet below); for anyone else the board is unchanged and has no buttons.

- **Attendance history from `/display`** (`src/AttendanceHistory.jsx`/`.css` over the pure `src/attendanceHistory.js`; 2026-10-01). The Team Hours drill-down became one shared view: a staff viewer (mentor, lead or admin) clicks a name on `/display` to open that member's history, read-only there because the board is often a staff session left open on a shared shop screen (decision 36), while Team Hours passes in its own staff controls (+ Manual session, Edit, Void). `App.jsx` passes `hasRole` to `PresenceBoard`; a non-staff board has no buttons at all. The staff-only rule is a UI rule: the Team Hours drill-down already shows any member's sessions to any member.

- **Quick pulse** (`src/QuickPulseControl.jsx`; 2026-10-19, Mr. Pina). On `/display` a staff viewer taps a name and gets a Sign in now / Sign out now button above the history. The first tap arms it ("Tap again to sign Riley in", disarms after 5 s), the second writes through `staff_add_event` (staff only, reason "Staff override from the presence board", an `attendance_audit` row, `manual_entry` true). With a sign-out request waiting (0014) the button reads Approve sign-out and approves it, so the member's note lands on the OUT. The sessions in the panel stay read-only (decision 36). Non-staff boards have no buttons.

- **Three layouts to choose from** (feedback a51bdc10, 2026-10-28): `?layout=shop` (default: sub-team coverage strip, a card per person in the shop with sub-team, sign-in time and time in, then everyone not here as compact chips by sub-team), `teams` (one tile per sub-team with present/total, its present cards and its absent chips) and `timeline` (present people on one shared time axis from the earliest sign-in to now). Links in the footer switch layouts; once Mr. Pina picks one, the others are removed. Parent-only accounts are no longer on the board (read from `member_roles`; when that read fails nobody is left out). Every member is still exactly one `.pb-row` with one `.pb-name`, a button only for staff, so `display-history.mjs` holds unchanged; `team-pulse.mjs` covers the layouts.
- **FRC or FLL on the board** (feedback 37b5feee, ledger 0028c): each present row shows which hours the open session counts, "FRC" or "FLL volunteer", from its IN's category (`computePresenceDetail`, `sessionKind`; the Check-in file has the rule). The board's `attendance_events` read now selects `category` (`tools/e2e/features/display-history.mjs` pins the column list).
