# Check-in

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- Check-in/out with NFC deep-link fast path. Geofence at 34.041550 / -118.086826, 150m radius (check-in gated to location, check-out always allowed). **iOS reliability**: check-in geolocation fires from a "Confirm check-in" tap (a gesture), not on load (`verifyAtShop` uses `enableHighAccuracy`/20s/`maximumAge:0` and rejects fixes coarser than 100m as `reason:'imprecise'`). **Hour category at check-in**: `/checkin` has NO category picker (only unused `.checkin-cats` CSS remains in `CheckinPage.css`); its IN always carries `DEFAULT_CATEGORY`, **build**, written to `attendance_events.category` on the IN event only (the OUT just closes the open session — the hours math attributes a session by its IN category). Categories live in **`src/categories.js`** (tiny, no React/Supabase deps so the fast path stays light): `build`(default)/`outreach`/`volunteer`/`competition` (reduced from six — `fundraising`/`mentoring` were dropped, see `supabase/categories_reduce_event_kind.sql`), each with an `--hr-*` theme color; helpers `categoryLabel`/`categoryColor`/`normAttendanceCategory`(legacy `'normal'`/null→`build`)/`loggedTypeToCategory`/`emptyBreakdown`. **Per-student geofence exemption**: `profiles.geofence_exempt` (bool, default false; no SQL file in this repo creates the column, decision 26) — staff toggle it on the roster (`Geo exempt`, direct `profiles.update`, admin RLS); an exempt member's check-in skips `verifyAtShop` and inserts directly (check-out unaffected). **Volunteer check-in (`/checkin-volunteer`, `VolunteerCheckinPage.jsx`)**: a second NFC fast path for summer FLL-room volunteering — same minimal layout + `CheckinRedirect` pending-URL bounce, but each session it opens is hardcoded to `attendance_events.category = 'volunteer'`. The category column is set by **`supabase/hour_categories.sql`** (supersedes the old `attendance_category.sql` normal/volunteer pair and the removed `volunteer_hours_backfill.sql`; default `'build'`), and the check constraint was later reduced to the four current categories by **`supabase/categories_reduce_event_kind.sql`** (`check in ('build','outreach','volunteer','competition')`; re-tagged existing `fundraising`/`mentoring` → `outreach`) — **must be applied or category-tagged inserts fault**. Same-tap toggle checks out an open volunteer session; tapping while a non-volunteer session is open auto-switches (closes it with an OUT, opens volunteer). Its geofence is the **FLL room (34.042134 / -118.086326)** via `verifyAtFLL`; `geo.js` now shares one `verifyAt(lat, lon)` core (same 150 m radius + 100 m accuracy floor + `enableHighAccuracy`/20s/`maximumAge:0`) behind `verifyAtShop`/`verifyAtFLL`. Both check-in paths insert client-side (there is **no** check-in RPC); RLS own-row is the server-side enforcement. Whether a tap checks in or out, and whether a page shown again may write at all, is decided by the one "checked in" rule (the `src/attendanceState.js` bullet below): a re-shown `/checkin` never writes.

- Kiosk check-in — **REMOVED** (was a shared-tablet Web NFC toggle via `staff_override_attendance`). The `/kiosk` route, `KioskPage.jsx`/`.css`, nav entry, and context tag were all deleted (it had been deactivated/commented for a while). `staff_override_attendance` RPC + `src/presence.js` remain (presence.js still used by PresenceBoard); restore from git history if ever needed.

- Auto-checkout at 10 PM via pg_cron; auto-closed sessions are flagged for mentor review before counting.

- **One "checked in" rule** (`src/attendanceState.js`; 2026-10-01). `currentStatus` decides it for the dashboard tile, both tag routes, the presence board, the glance, the parent view and the Team Hours In/Out pill: the newest event is an IN from today in Los Angeles or still inside `MAX_SESSION_HOURS`, so an evening session counts past midnight (decision 29). **A re-shown `/checkin` or `/checkin-volunteer` never writes**: each stamps its history entry as handled before writing, so a back gesture, a reload or a restored tab shows "Checked in since … [Check out]" and waits for a tap. The silent toggle on re-show was the 2026-09-08 check-out report. A fresh tag tap is a new navigation and still checks out with zero taps; a browser that reuses the tab for a repeat tap pays one tap (decision 28, `test:checkin` step R7). A failed status read shows "Status unavailable", never the check-in prompt, and the duplicate-tap window also checks the device's own record of its last tap.

- **Sign-out requests and meeting check-in** (`supabase/migrations/0014_session_signout.sql` + its test, `src/signout.js`, `src/SignoutForm.jsx`, `src/SignoutsPage.jsx`, `src/dev/fixture/features/signout.js`, `tools/e2e/features/signout.mjs`; 2026-10-19, ledger 0009). Handbook Sections 6 and 7. Once 0014 is pasted, a tag tap (or the dashboard Check Out) with a build session open shows a note form (typed, or spoken through the browser's own speech recognition, no audio kept) and a cleanup tick, and sends a request; hours stop when an approver approves, which writes the OUT carrying the note. Approvers are staff and holders of the `signout.approve` capability (granted on `/roster`), never for their own request; `/signouts` lists the queue with Approve, Not yet (send back with a reason) and Approve all, who is signed in, and today's decisions naming who decided. A trigger refuses a non-staff member's own OUT on a build session; FLL (volunteer) sessions still sign out directly with the note, and `switch_to_fll` closes a build session and opens the FLL one in one call. A scan during a `kind = 'meeting'` event logs `meeting_checkins` present in its first 15 minutes, late after; a member already signed in keeps the session open. Staff sign out directly with the note. Before 0014 every page checks out with one tap, exactly as before (`test:checkin` and `dashboard-checkout` pin that path with migrations 0001 to 0013). `MAX_SESSION_HOURS` is 12 (handbook: the 12-hour open-session flag).
