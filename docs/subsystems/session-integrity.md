# Session integrity

Moved verbatim from `CLAUDE.md` (The subsystems) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- **Session-integrity tooling** (`supabase/session_integrity.sql`). A "session" is a DERIVED IN/OUT pairing from `attendance_events`, never a stored row. **(1) Forgot-to-sign-out cap** — implemented at derivation time in `hoursUtils.js` (NO synthetic events written): `MAX_SESSION_HOURS` (config constant, default 10h — the one knob; derives `MAX_SESSION_MS`) + `cappedSession(inTime, outTime, {maxMs, eventEnd})` clamp each session's end to `min(eventEnd if tied to a calendar event, IN + maxMs)`. A still-open session UNDER the cap stays live + uncapped; the cap only bites once it goes stale (open past the cap) or a closed pair exceeds it. `cappedSession` is applied in `sessionsFromEvents`, and so reaches `buildBreakdown`, `computeHoursMs`, `computePendingMs` and the Team Hours Matrix's `hoursByDay` (HoursBoard's own `attendanceHoursByDate` was deleted on 2026-10-01), all of which now read sessions from it. Sessions carry a computed `wasCapped` flag (+ `inId`, `manual`) — NOT a DB column; shown as a `capped` badge on My Hours + the Team Hours drill-down. The `eventEnd` clamp is supported by the helper but not yet wired (no consumer currently loads calendar events into the hours path). **(2) Audit trail** — `attendance_audit(event_id, member_id, actor_id, action[insert|edit|delete], reason, old_value jsonb, new_value jsonb, created_at)`; RLS staff-read + member-reads-own, **no client writes** (only the SECURITY DEFINER RPCs insert). Shared infra for (3) and (4). **(3) Admin manual entry / adjustment** — `attendance_events.manual_entry` bool col; staff (`is_staff()`) RPCs `staff_add_manual_session(member,in,out,category,reason)` (inserts a matched IN/OUT pair, `manual_entry=true`, method/location `'manual'`, verified), `staff_edit_event(event,time,category,reason)`, `staff_void_event(event,reason)` (hard-delete, snapshotting old_value first); all require a reason + write the audit via the shared `_apply_event_edit` helper. UI lives in the **HoursBoard drill-down** (staff "+ Manual session" button + per-session Edit/Void via `AdjustPanel`; reloads events after). Off-site non-shop hours stay on `logged_hours` + its existing verification — not rebuilt. **(4) Correction requests** — `session_corrections(member_id, checkin_id, checkout_id, note, proposed_in/out/category, status[pending|approved|rejected], resolution_note, reviewed_by/at)`; RLS member-reads-own + staff-read, writes via RPCs `request_session_correction(...)` (student, validates the referenced events are theirs) and `resolve_session_correction(id, approve, resolution, apply_in/out/category)` (staff; approval applies the edit to the underlying events via `_apply_event_edit` so it audits, idempotent). Student flow: a **Flag** button per recent session on My Hours opens a note+proposed-values modal; status shows in a "Correction requests" card. Staff flow: a **Correction Requests** queue on `/verify-hours` (`VerifyHoursPage`) mirroring the logged-hours verify/reject UX, with editable apply-values before approving. **(5) Logged-hours corrections** (`supabase/logged_hours_corrections.sql`) — the same flow but for **manual `logged_hours` entries** (a different table from the derived-session corrections in (4)): `logged_hours_corrections(member_id, entry_id, note, proposed_type/hours/date, status, resolution_note, reviewed_by/at)`, partial-unique one-pending-per-entry, RLS member-reads-own + staff-read, writes via SECURITY DEFINER `request_logged_hours_correction(entry, note, type, hours, date)` (member; entry must be theirs) and `resolve_logged_hours_correction(id, approve, resolution, apply_type/hours/date)` (staff; approval applies the coalesced edit to the underlying `logged_hours` row, idempotent). Member flow: a **Request correction** button per **verified** entry on `LogHoursPage` opens a reason + proposed-values modal (shows "correction pending" while open). Staff flow: a **Logged-Hours Corrections** queue on `/verify-hours` with editable apply-values.
