# Guided app training

`/training` is linked from Home, Training / Replay tour inside the account menu's Preferences group, and Team admin's Training progress tile. It replaces the old driver.js overlay. The existing feature catalog (`src/featureGuide.js`) and its route drift test remain the inventory of every feature. `src/tour/catalog.js` builds six walkthroughs from that catalog: member, scout, driver, pit, mentor and parent. Scout, driver and pit are chosen learning tracks, never database roles or permission grants. Staff default to Mentor; a parent who is also staff follows the staff rule. The actual admin flag controls admin-only lessons, matching the shared search catalog.

Core member activities cover FRC and FLL check-in, sign-out, absence requests, schedule views, role requests versus assignments, offline scouting, battery filters, match-log views and feedback. Attendance and sign-out practice change no attendance. Absence practice uses the production `AbsenceForm` and `absenceProblem` validator with a local callback that returns before its RPC. The sample meeting is seven days ahead. The real request stays on My standing. Scouting's existing practice workbook remains separate and awards no certification. Parents get their dashboard, schedule, family/standing guidance and feedback, followed by the features their account can use. Restricted robot tools do not become parent routes.

After core, every track practices the real Search control, finds a page and closes the native modal without pausing training. The lesson also explains My record and Preferences. Then every feature in the account's guide is a guided reference or a visit to the real page. Scout, driver, pit and mentor tracks order their relevant tools first. NFC routes and private capability links use reference cards with their real entry point, never a fabricated token or an automatic check-in navigation. Competition-specific routes use the event explicitly chosen by the learner. Trips and individual robot matches keep their own record IDs, so they use reference cards instead of substituting a competition ID. A competition lesson without a chosen event is blocked and can be skipped.

`Runner.jsx` highlights literal stable `data-tour` targets. It never silently drops a missing target: Continue is blocked and a setup/missing-target message appears after the wait. The learner can pause or skip. Core completion requires every core activity, so a skipped core step remains unfinished until revisited. Library steps are optional. The guide's route test and `tests/tour.test.js` check both coverage and actual JSX target declarations, including removed-anchor and selector-string negative controls.

The guidance is a named non-modal region: the page stays keyboard-accessible for hands-on work. Tab and Shift+Tab follow native controls, F8 moves between guidance and the highlighted feature, Escape pauses outside another open dialog, and pause restores focus to the opener or account button. Step changes have a polite live announcement. No smooth scroll or animation is added. The dock leaves page space beside it on computers and below it on phones; feedback is moved clear of it while training is active. It uses the app fonts, theme tokens and plate housing/key geometry.

Resume state is versioned and scoped to the signed-in member in localStorage under `techmen:training:<member id>`. It records the current lesson ID, done/skipped lesson IDs, track and event ID, with no names, emails or form text. It survives reload on this device; changing accounts remounts the provider and never resumes the previous member's state. Blocked storage has an explicit warning and keeps the current tab usable. Resume is not synchronized between devices.

Migration `0047_core_tour.sql` adds `tour_completions`, keyed by member ID and core version. `tour_complete_core(track, version)` checks an approved active account and the track's role boundary, derives the member from `auth.uid()`, stamps the server time and keeps the first completion on retries. Completion is self-reported, not a certification or an access gate. No direct client writes are granted. Authenticated callers may select only their own row, or all rows if active approved staff. `tour_completion_overview(version)` is active approved staff only and left joins the active approved role-bearing roster so unfinished members remain visible. It returns display names, never emails. Both RPCs grant execute only to authenticated; public, anon and service_role are explicitly revoked. Account merges know the new member reference, and an existing kept-account completion wins.

The mentor view defaults to unfinished members, with search, all-members toggle and refresh. Missing migration, failed read, loading and an empty filter result are distinct. Core saving has pending, saved, missing and retry states; no missing-RPC fallback can claim success. Legacy `profiles.onboarded_at` is not training completion, and neither finishing nor dismissing the old overlay grants credit.

Verification lives in `tests/tour.test.js`, `tests/write-via.test.js`, `tools/e2e/features/tour.mjs`, `0047_core_tour_rls_test.sql` and `tools/sql-harness/mutants-0047.mjs`. Browser fixtures prove rendering and local practice; real PostgreSQL tests prove database permissions. Neither proves live Auth/PostgREST, real mobile NFC, iOS, screen-reader hardware or production migration installation. See this job's history for measured results and commands.
