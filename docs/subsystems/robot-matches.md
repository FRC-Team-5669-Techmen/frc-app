# Robot match log

Built by ledger 0028 (migration 0038) for Beach Blitz 2026: every match the robot plays, practice or real, becomes one record that joins what the robot measured with what people saw.

- **Where the data comes from.** The robot repo (`FRC-Team-5669-Techmen/2026-5669-Official`, public) writes one JSON file per match, schema 1, defined by `src/main/java/frc/robot/practice/MatchTelemetry.java` and `subsystems/PracticeMatch.java`. The driver station laptop's `tools/match-data/Sync Match Data.bat` pushes them to `match-data/matches/<yyyyMMdd-HHmmss>_<kind>_<n>.json`. `startedAt` is the robot's wall-clock time with no zone; the app reads it as Los Angeles time (`startedAtMs`, `_rm_started`). Kinds: practice, qual, playoff, practice_fms, auto_test, teleop_session (and fms).
- **Pages.** `/robot/matches` (`src/RobotMatchesPage.jsx`): Log (filters kind, event, driver, battery, date range in the URL; a card per match with balls in, closed hub, ready %, min V, brownouts, hang time; tick two to six to compare), Trends (per driver: balls in, closed hub, ready %, hang with sparklines; per battery: lowest and average minimum voltage, brownouts) and Compare (one row per number, best marked where higher or lower is better). `/robot/matches/:id` (`src/RobotMatchPage.jsx`): scorecard, battery by phase, not-ready reasons, timeline, crew and links, notes, video, the robot file whole with a download, and an edit form for writers. Linked from the Robot hub tile and the Match simulator header. Parent-only accounts are told it is for students and staff. Styles: `src/RobotMatches.css` plus the battery page's `.ba-*` classes.
- **Import** (`src/RobotMatchImport.jsx`, writers only): Pull from GitHub (the public contents API, then raw downloads; at most 80 files per pull) or drop files. A preview per file before anything is saved: typed crew names matched to members (exact preselected; a loose match must be chosen, so a guess is never applied), battery label (B7, b07 and "B 07" are B07), auto name (offer to add a missing routine), the Match Sim record it joins, the event, and the battery run and drive time it will log.
- **Rules in one file, `src/robotMatches.js`** (pure), read by the pages, the import and the connector: parsing, the compared columns (`COLUMN_PATHS`, held equal to 0038's `_rm_extract` by `tests/robot-matches.test.js`), labels (qm12, pm3, playoff 4, practice 7), name matching, the merge rule, trends and compare. Balls in is the scorer's count when someone counted, else auto plus open hub. A number the robot did not record is `--`, never 0.
- **Database (0038).** `robot_matches`: one row per match. `raw` is the whole file (unknown fields kept), `file_name` unique (re-importing changes nothing, status `already`), the compared numbers in real columns, the typed crew in `crew_typed`, people's fields (scorer balls in, TOWER, fouls, score, RP and where they came from, notes per role, video, `.wpilog` name), links to profiles, batteries, auto routines and events, and the battery run, drive session and auto run it wrote. Read by `_driver_member_ok()`; no client write grant. Writes are SECURITY DEFINER functions for staff or the `robot.matches` capability ("Can log robot matches", for drive-team leads): `robot_match_import(file_name, raw, links)`, `robot_match_update(id, fields)` (an allow-list of people's fields), `robot_match_fill_official(id)`.
- **One match, one record.** A trigger on `sim_matches` keeps a `sim_page` row for every Match Sim save (and 0038 backfilled every existing one). Importing a file that started within 5 minutes of the one file-less Match Sim row on the same alliance (or the one named in `links.sim_match`) merges into it: same id, source `both`, people's fields kept.
- **Linked rows, once per file.** On import: one `battery_runs` row through `battery_log_run` (voltage before and after = battery start and end, brownout yes when brownouts > 0, match kind for real-field kinds, practice match for practice, drive practice otherwise; skipped when the Match Sim row already wrote one or the match is more than 60 days old) and one `drive_sessions` row for the driver (minutes from `durationSeconds`, kind match for real-field kinds, practice field otherwise). The Driver Score formula (`src/driverScore.js`) is unchanged; match performance in it is decision 52.
- **Real event matches.** A qual, playoff, field practice or FMS match links to the one competition running (a day either side). If that event's scouting has imported The Blue Alliance results, the alliance score and RP fill from them (team 5669's `official_results`, by match key and alliance).
- **Connector.** Reads: `list_robot_matches` (filters, optional trends), `get_robot_match` (the full stored file), `compare_robot_matches`. Writes (always ask first): `import_robot_matches_from_github` (no file lists what is new and writes nothing; with a file it imports that one; a typed name that could be two members answers ambiguous until he names who) and `set_robot_match_notes` (`robot_match_update`). Matches resolve by label through `resolveRobotMatch` (a label played twice is ambiguous).
- **Proof.** `0038_robot_match_log_rls_test.sql` and `tools/sql-harness/mutants-0038.mjs`; `tests/robot-matches.test.js`, `tests/robot-matches-connector.test.js`; `tools/e2e/features/robot-match.mjs` on fixture mode (`src/dev/fixture/features/robotmatches.js`, which also wraps `sim_save_match` the way the trigger does). `verify:browser` boots only the `/_ds` specimen with no sign-in, so these routes are measured by the fixture E2E instead.
