Moved verbatim from `CLAUDE.md` (Database, and how SQL actually reaches it) on 2026-10-19, so `CLAUDE.md` stays short. `CLAUDE.md` links here; keep this file current in the same commit as any change to what it describes.

- **59 unnumbered SQL files, frozen where they are** (counted 2026-10-01; this line said 58, with 57 under `supabase/`): 56 directly under `supabase/`, one under `sql/` (`forgotten_checkout.sql`), and two at the repo root that this file never named before: `platform_foundation.sql`, the original members-and-roles design draft, whose header says to hand it to Claude Code rather than paste it, and `platform_migration.sql`, the reconciled version that was pasted (`member_roles`, `has_role()`, `handle_new_user()` and the base policies on `profiles`, `member_roles` and `attendance_events`). 52 of the 59 say in a comment that they are pasted into the Supabase SQL editor, some form of *"Run once in the Supabase SQL editor, BEFORE testing the UI"*. That line is the apply instruction and it is addressed to a person. Beside them, `supabase/migrations/` holds twelve numbered migrations (0001 to 0004 from 2026-10-01, 0005 and 0006 from 2026-10-04, 0007 and 0008 from 2026-10-05, 0009, 0010 and 0011 from 2026-10-06, 0012 from 2026-10-16), none applied to the live project when written; 0013 (2026-10-19) is the handbook signatures, and `docs/feedback/2026-10-01/MARK_DONE.sql` is a one-off data paste, not a migration.

- **Thirteen have a `_rls_test.sql` sibling**: three frozen ones — `feedback`, `member_applications`, `parent_responses` — and the ten numbered migrations that touch a policy or a grant (0006 is a data seed and 0011 changes no grant or policy, so neither has one; 0011 is proven by `tools/sql-harness/check-0011.mjs` instead), each running inside a `begin … rollback` so it is safe against live data, and each carrying positive controls so a broken-shut policy cannot fake a pass. The numbered tests return one row per check (check, result, detail), because the SQL editor shows no NOTICE output. That is the proof pattern where one exists.
