 Earlier — HOST TRANSPARENCY — the design system stopped assuming its children are its direct children. FULL INVENTORY FIRST, reported before a line changed, because the ask was one mechanism rather than a sixth patch: three guards type-checking a slotted child (SafetySheet's `child.type === SafetyNote`, SponsorTier's ImageFrame/Cutout test, CalloutDrawing's `frcPin`), six positional or prop-reading walks (JumpGrid/ProcessPipeline/CalloutDrawing `cloneElement(child, {index})`, SubteamStatus's `slots.subteam.props.children`, FieldDiagram's `l.props['data-zone']`, and `slotted()` itself), DeckStage's `stage.children` filter, and 8 of the 21 `>` selectors in tokens/. THE QUIET ONE WAS `slotted()`: painting the system class onto a `display: contents` host still inherits colour and font and silently drops every box property, so a hosted sheet looks NEARLY right — which is why it had never been reported. THE ONE THAT FAILS OPEN was SponsorTier: left as a direct-child type check it did not trip on a hosted deck, it stopped guarding. Approach chosen and the alternatives said out loud: a JS-stamped `data-frc-host` class driving `:where(X, X [data-frc-host]) > Y` in CSS was the first candidate and was REJECTED — it makes layout correctness depend on a component being mounted, and the pre-stamp frame of `.frc-stage > .frc-sheet` failing means every sheet paints at once. VERIFIED IN A REAL BROWSER at /_ds, headless Chromium against the dev server, in a NEW `host` section that mounts the real components through a MODELLED host and measures rather than asserts — and it is named as a model, plainly, because the runtime is not available here: three wrapper flavours carrying three DIFFERENT signals (a custom element with inline display:contents; `dc-host`, transparent from a STYLESHEET only with nothing readable in its props, which is the case an inline-style test misses; and a plain `<span data-frc-host>`, the case a tag-name test misses), each mounted BOTH with `slot` hoisted onto the wrapper and with `slot` left on the child. RESULTS: SafetyNote guard 10/10 — all six hosted arrangements PASS, the direct child still passes, and all three wrong-content cases (Callout through a host, SafetyNote buried in a Card through a host, no note at all) are still REFUSED. DeckStage: 2 of 2 sheets hosted (parents `x-host`/`dc-host`, both computed `display: contents`), active `display: block`, inactive `display: none`, painted `--bg0 #E9E7E1 · --edge #DCD9D1` — a PAPER sheet chosen as the active one on purpose so the two tones DIFFER, which is what proves it read the active hosted sheet rather than reusing one tone or reading the squadron deck root. Slotted copy: `frc-sheet-title` measured on the author's `<h2>`, the `x-host` above it carrying an empty class. Numbering: Part 01 / 02 / 03. NEGATIVE CONTROLS RUN IN THE BROWSER TOO, because a proof that cannot fail proves nothing: reverting the four fixes reproduced the reported failures exactly — the three slot-on-the-host guard cases flipped to REFUSED, BOTH sheets went to `display: block` (every sheet painting over every other) with DeckStage falling back to `#000000/#000000`, and `.frc-sheet-title` vanished from the subtree. Restored, all five verdicts PASS, zero FAIL verdicts anywhere on the route, 4 fault markers which is the documented DeckStage baseline. ds:audit check 29 added holding both ends, with 7 new negative controls (45 total). NOT DONE, deliberately: no sheet pattern's public API changed, no new required prop anywhere, and the numbering walkers were made host-aware as defence in depth even though `pickSlots` already covers them transitively — check 29 is what keeps that true. Verified: ds:audit ok at 78 components / 290 files, production build clean, DS still absent from dist.
