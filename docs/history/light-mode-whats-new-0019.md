A light theme now exists beside the Tactical HUD dark one, chosen per device on the profile (Appearance) or in a new Theme row in the account menu. Dark stays the default, because every current user has only ever seen dark, and System follows the device. The choice lives in localStorage (`techmen:theme`, every access wrapped) and is painted before first paint by a tiny inline script in `index.html`, so there is no flash and the check-in routes import nothing new. That script repeats `resolveTheme()` from `src/themeMode.js` on purpose; `tests/theme-mode.test.js` runs the script itself in a sandbox for every stored value and both system preferences, requires agreement with the resolver and the theme-color meta, and carries a mutant (the script forced to light) that the same comparison must catch.

The light tokens are the team design system's projector palette. The design problem was gold: 633 rules used `var(--gold)`, mostly as text and thin borders, which would be unreadable on white. Rather than touch 600 text rules, the light block turns `--gold`, `--gold-bright` and `--gold-dim` into ink and steel, and a scripted sweep moved every gold BACKGROUND (135 declarations in 47 stylesheets, plus the inline check-in confirm keys) to new fill tokens `--gold-fill*` that stay Techmen Gold in both themes, with `--on-gold` for text on them (84 rules, plus six found by two more passes that looked for text rules on gold-filled classes and their descendants). In dark every new token carries the old value, so dark renders as before. Hard-coded colors that broke light were converted: the job status chips (new `--ok` and `--warn`, dark values equal to the old literals), and text on alliance and fault fills (`--on-strong`). The plate's highlights and shades are inverted in a light block (highlights from `--bg`, shades from `--text`), and the gold mark swaps to the black one by a CSS `content` rule.

What's new is `/updates`, built from `src/updates.js`: eighteen releases seeded from this tree's git log (six commits, the 0017 parts and their predecessors) and from `docs/history/` titles, each claim checked against its subsystem doc. The unread rule compares the newest entry's `date|title` with the one stored when `/updates` was last opened, so a second release on the same day still lights the dot and a rolled-back build does not. The dot shows on the avatar, the menu item and a one-line strip at the end of Home. Adding the menu item made a student sign-out approver's menu seven entries against decision 49's six; decision 50 records that, with the default of keeping it and two alternatives. `tests/nav-admin.test.js` now allows seven only on that path.

Measured: `tools/e2e/shoot.mjs` gained `--theme` (it refuses a shot whose `data-theme` does not match) and photographed Home, `/robot`, `/scouting`, `/batteries`, `/updates`, `/profile` and `/checkin` in light and the five in dark at 375 as a student, and eleven admin routes in light; each was looked at, and the illegible ones (job chips, the battery filter count, alliance buttons) were fixed. `tools/e2e/features/theme-updates.mjs` is the kept harness: default dark, Light from the menu repaints white with ink titles and stays open, survives a reload, the dot present (1) before and absent (0) after visiting `/updates`, cards newest first, Dark from the profile returns gold titles.

Not done: pages outside the screenshot set were swept by the codemod and by grep but not each looked at in light (the event family hub, the member application, login and the access gate render with the same tokens and were not photographed). Print styles are untouched. CLAUDE.md was already over its 4,000-word ceiling (4,180) before this bundle; it is now 4,193.
