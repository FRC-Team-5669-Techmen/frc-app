 Earlier — Team LOGOTYPES wired, the SEAL refused, and RoleCard given a density and a media slot. PART A: Type-{Gold,White,Black}.svg were fetched from the canonical paths linked off https://frcteam5669.com/outreach/branding, given exactly the treatment the Marks already had -- copied into assets/team/, imported in assets.js beside the mark imports, recorded in assets/PROVENANCE.json with source URL, sha256 and byte count -- and ds:audit's existing check 13 now hash-pins them. RECOLOR CHECK, the whole reason this is done by hand: Type-Gold carries #ffe629 in all 16 of its colour declarations, identical to Mark-Gold, no #D4AF37 and no other near-gold; White is #fff and Black is #000000 in all 16; the three variants were proved byte-identical apart from the fill by normalising each fill to a placeholder and diffing. THE SEAL FAILED THE SAME CHECK AND WAS NOT ADOPTED: the published 5669-Seal.svg carries #ffe623 in all 71 of its gold declarations (41 stroke, 30 fill), a near-gold differing from #FFE629 only in the blue channel (0x23 against 0x29) -- invisible at seal scale, which is precisely the drift the provenance file exists to catch. The fetch was repeated cold and both downloads hash identically, so it is the published artwork rather than a transfer fault. ASSETS.seal stays null, SealMark keeps its marked empty slot, and the refusal is recorded in a NEW `rejected` block in PROVENANCE.json carrying the hash of what was refused, so nobody re-fetches it and adopts it without looking. The blocking symptom cleared anyway: DeckFooter defaults to mark="logotype", so 32 of 32 footer rails in /_ds measured a FILLED logotype and zero empty boxes; the only seal slots left are the three SealMark demos. MIN_SIZES.logotype and a new LOGOTYPE_RATIO were moved onto the real 1049.669 x 287.139 aspect, replacing the 5:1 placeholder the code itself flagged as standing in until the file landed -- measured 73 x 20 at ratio 3.6562 in the rail. A REAL BUG WAS FOUND BY WIRING THE ARTWORK AND IS FIXED, NOT DEFERRED: variant="auto" switched Gold/Black with DESCENDANT SELECTORS, and a deck nests grounds -- a paper sheet sits inside a squadron deck root -- so `.frc-ground-squadron .frc-mark-auto > [data-variant="gold"]` matched from the outer scope however near the paper scope was, while paper's own rule only switched black ON. Both variants displayed and Techmen Gold painted on paper, which the system forbids. It was invisible while the Type slots were empty (an empty slot paints no gold) and the gold-on-paper proof could not see it either, because that proof reads computed colour and an <img> of a gold SVG carries none. Now driven by inherited custom properties --mark-auto-gold / --mark-auto-black, which resolve against the NEAREST declaring ancestor, with the dark-ground answer as the fallback so a groundless deck root behaves as SQUADRON; declared with :where() so a ground class beats it outright rather than by source order. MEASURED in the live route after the fix: 68 auto-variant children across all three grounds, 0 offenders. The two gold slots still visible on a paper tab are explicit variant="gold" in the BrandDemoCard, which is a specimen showing the three published variants, pre-existing and orthogonal. PART B: RoleCard gained density="default"|"compact", an optional slot="media" (slot="portrait" still works, unchanged call sites keep working, no new required prop), slot="note", and a wrapper class frc-role-grid. Cause on record: a generated deck placing nine RoleCards hand-wrote gridTemplateColumns, padding, gap and font-size from the deck plus an inline paragraph per card -- a deck reimplementing a component -- because the component could not express what was needed. The card now owns its type scale, padding and gaps; the grid class owns the columns and the gutter, which is the one thing a card cannot own. An empty media slot renders the system's own frc-frame-empty affordance sized to the slot, the same override a Cutout takes and for the same reason. NEW /_ds section `role-density` MEASURES rather than asserts, and every card in it is mounted with no style prop at all: name font-size 64px default against 40px compact, padding 32px against 16px, row-gap 32px against 16px, grid tracks 2 (media beside) against 1 (media above), card radius 4px, frc-role-grid resolving 6 columns at a 24px gutter on a 1920 stage so nine compact cards land 6+3 with nobody counting, filled slot holds an img and no marker, empty slot dashed 1px on transparent, and ZERO inline font-size/padding/gap/grid-template on any card or any descendant.
