 Earlier — Discord calendar posting PORTED off Vercel to a Supabase Edge Function + pg_cron, same day it was built. CAUSE: Vercel's Hobby plan caps cron at one invocation per day, which cannot support a 2-hour reminder. api/ is DELETED (discord-calendar.js, _lib/, README.md) and vercel.json is byte-reverted to the plain SPA rewrite — no crons block, no /((?!api/).*) — so there is no half-migrated second path. The three engine modules were MOVED, not rewritten (git mv api/_lib/*.js → supabase/functions/discord-calendar/lib/), and the 12 tests import the moved files and still pass 12/12. They already ran on the Deno∩Node intersection (plain ESM, explicit file extensions, node:crypto only) so no logic changed — only the api/-era header comments. NEW supabase/functions/discord-calendar/index.ts is the entrypoint: Deno.serve, secrets from Deno.env, service-role client, and the SAME invocation auth the other functions use — `x-cron-secret` header vs the DISCORD_CRON_SECRET function secret, mirroring send-push/cron-notify's x-push-secret/PUSH_SECRET; the CRON_SECRET bearer check is gone. Deploy --no-verify-jwt (shared secret, not a JWT). NOTE this is the ONLY function in supabase/functions/ that is not single-file, so it cannot be Dashboard-deployed — that was a deliberate trade against duplicating the no-double-post engine, and it is called out in its README and index.ts. Scheduling was APPENDED to supabase/discord_calendar.sql as section 4 (one file to run, fully re-runnable: unschedule-if-exists then cron.schedule): pg_cron + pg_net extensions, private.discord_calendar_config (edge_base_url + hook_secret, RLS on with no policies), SECURITY DEFINER public.invoke_discord_calendar() posting via net.http_post, and cron.schedule('discord-calendar-hourly','0 * * * *'). Config is a SEPARATE row from private.push_config on purpose — filling push_config activates the push triggers/crons and that deploy is still on hold, so sharing it would force one release to ship before the other; null edge_base_url = no-op, which doubles as the pause switch. Report-only remains the default and is still controlled solely by DISCORD_CALENDAR_MODE (only the literal 'live' posts); the request body can only DOWNGRADE to report. Also corrected the stale provisioning note that said apply was blocked on the bot's role position — provisioning COMPLETED, roles/categories/channels are live in the guild, only AutoMod did not land and it is unrelated to this feature.
