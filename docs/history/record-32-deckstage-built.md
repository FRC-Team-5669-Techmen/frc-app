 Earlier the same day — DeckStage built; the deck shell demoted to reference. The shell stopped being a starting point, so its stage script had nowhere to live: it is now components/brand/DeckStage.jsx, the one component that is behaviour rather than appearance, and every deck mounts it EXACTLY ONCE. It renders nothing visible and paints the canvas, the letterbox and the thumbnail frames from the ACTIVE sheet --bg0 and --edge, repainting on every sheet change. --edge is the whole job: the generated deck rolled its own stage logic and read --bg0 but never --edge, which is precisely the white flash a transition exposes; reading the tones off the active SHEET rather than the deck root is what stops a paper sheet sitting in a black letterbox. It does not own the deck root - it walks up to .frc-deck and READS - and six states trip the shared rust marker (throwing only under harness mode): no .frc-deck ancestor, no .frc-stage, no data-aspect, no ground class, no audience class, a second instance. The middle four are exactly what a Blank-generated deck lands in. ONE RULE ADDED BEYOND THE BRIEF, deliberately: the DOCUMENT canvas is painted only when the root carries .frc-letterbox, which is what declares that the deck owns the viewport - without it a demo card or a proof would repaint the whole host page. Ships .jsx/.d.ts/.prompt.md, wired into brand/index.js, the Brand demo card (a live miniature deck with two sheets on different grounds and a thumbnail rail) and the manifest; registry is now 78 components. VERIFIED AT /_ds with a new DeckStage section that measures rather than asserts: three correct decks (one per ground) and all four broken states.
