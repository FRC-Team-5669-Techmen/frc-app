 Earlier same day — the original Vercel build — NEW api/discord-calendar.js + api/_lib/{discord,render,calendarSync}.js + supabase/discord_calendar.sql + api/README.md + scripts/discord/calendar-sync.test.mjs; vercel.json gained a `crons` block and its SPA rewrite was narrowed to /((?!api/).*) so it cannot swallow the function; .env.example + package.json (discord:calendar:test) updated. AUDIT FIRST, and it decided the design: (a) events live in THIS app (public.events, Supabase) — Google Calendar is a consumer of it via the calendar-feed Edge Function, not a source; (b) the existing serverless pattern is Supabase Edge Functions (7 of them) and there were ZERO Vercel functions and no api/ dir before this, so this establishes that pattern; (c) no Vercel cron existed and vercel.json held only the SPA rewrite. Two schema gaps shaped the build and were NOT papered over with invented columns: events has no `cancelled` column (staff cancel by DELETING the row), so cancellation is detected as "we posted about it and it no longer exists" — which is why discord_calendar_posts has NO foreign key to events and carries an event_snapshot jsonb, since a cascade would erase the evidence at the exact moment it is needed; and events has no subteam column, so the ping rule is taken literally, word-matching the src/subteams.js vocabulary in title+notes against the SERVER_SPEC §3 role names (Fabrication/Robot Construction/Field & Pit have no Discord role and ping nobody). Core correctness is a DB constraint rather than app logic: unique (event_id, post_kind) plus reserve-then-send, and an AMBIGUOUS Discord failure keeps the reservation as 'pending' forever rather than risking a duplicate ping — only a definitive 4xx releases it. Report-only is the default and writes to the log table ONLY, never to the tracking table, so dry runs do not burn dedupe keys. Verified the bot token cannot reach the browser by building with canary values in env and grepping dist/ for both the names and the values — clean, and api/ is not in the Vite graph at all. 12/12 in-memory tests pass (npm run discord:calendar:test). Run supabase/discord_calendar.sql before switching DISCORD_CALENDAR_MODE to live.
